# ADR-001 — Технологический стек

Статус: **принято** · Дата: 2026-09-09 · Основание: ТЗ §3, §37

## Решение

| Слой | Выбор | Соответствие ТЗ |
|---|---|---|
| Desktop shell | **Rust + Tauri 2.x** | §3 — как в ТЗ |
| UI | **React 18 + TypeScript + Vite** | §3 — как в ТЗ |
| System layer | **Rust** (`rust/*` крейты, `SystemAdapter`) | §4, §30 — как в ТЗ |
| Agent Core | **TypeScript** (`core/`) | ⚠️ отличие от ТЗ (было: Python) |
| ML-рантайм (STT/VAD/wake word/embeddings) | **Rust**: ONNX Runtime (`ort`) + `whisper-rs` | ⚠️ отличие от ТЗ |
| Python | **опциональный рантайм плагинов**, не ядро | ⚠️ отличие от ТЗ |
| Storage | **SQLite** (`rusqlite`) + `sqlite-vec` для векторов | §3, §31 — как в ТЗ |
| Секреты | **OS secure storage** через `keyring` | §29, §31 — как в ТЗ |

## Почему Python убран из ядра

ТЗ §3 предлагает Python 3.12+ как отдельный локальный service layer. Это конфликтует
с целями §37 (startup < 3 сек, минимальный idle CPU/RAM) и с требованием
кроссплатформенной поставки из §2:

1. **Поставка на macOS.** Питоновский сайдкар нужно паковать PyInstaller/PyOxidizer,
   а затем подписывать и **нотаризовать вторым бинарём** — вместе с hardened runtime
   и entitlements для Accessibility/Screen Recording. Это отдельный релизный конвейер
   на каждую ОС и постоянный источник поломок при обновлении macOS.
2. **Размер бандла.** CPython + `numpy`/`torch`/`onnxruntime` — это +200…400 МБ к
   инсталлятору. Tauri был выбран (§3) именно ради лёгкости; сайдкар этот выигрыш съедает.
3. **Startup и RAM.** Холодный старт интерпретатора + импорт ML-стека — это 1.5–4 сек
   и 150–300 МБ RSS в простое. Цель §37 «startup < 3 сек» становится недостижимой.
4. **Второй процесс = второй failure domain.** IPC, health-check, перезапуск,
   рассинхрон версий, порты/файрвол на Windows.

Всё, ради чего в ТЗ нужен был Python, закрывается на Rust без потери качества:

| Задача | Python-вариант | Наш вариант |
|---|---|---|
| STT | faster-whisper | `whisper-rs` (whisper.cpp) / cloud API |
| VAD | silero-vad (torch) | silero ONNX через `ort` |
| Wake word | openWakeWord | та же ONNX-модель через `ort` |
| TTS | piper (python) | `piper-rs` / cloud API / OS TTS |
| Embeddings | sentence-transformers | ONNX-модель через `ort` + `sqlite-vec` |
| Оркестрация агента | LangChain и т.п. | свой цикл на TS — он и так описан в §5 явно |

## Где Python остаётся

- **Plugin SDK (§20)** — пользовательский плагин может быть Python-скриптом; рантайм
  подтягивается опционально и живёт в песочнице с permission review.
- **Dev Mode (§27)** — Yuki умеет запускать Python как инструмент пользователя.

То есть Python — это *возможность*, которую Yuki использует, а не зависимость,
без которой она не стартует.

## Последствия

- Один подписываемый бинарь на платформу → простой релиз (§2).
- Agent Core на TS шарит типы с UI без кодогенерации и IPC-сериализации.
- Локальные ML-модели скачиваются по требованию в `~/.yuki/models`, а не лежат в бандле.
- Плата за решение: часть ML-экосистемы на Rust моложе питоновской; при упоре в
  ограничение — путь отхода открыт через тот же plugin-рантайм.
