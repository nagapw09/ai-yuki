# Plugin SDK

Локальный SDK расширений Yuki (ТЗ §20). Публичного магазина нет: плагин ставится
из папки, из git-репозитория или создаётся самой Yuki (ТЗ §18).

## Что такое плагин

Папка с двумя обязательными вещами:

```
my-plugin/
  yuki-plugin.json   манифест
  server.py          программа, говорящая по MCP через stdin/stdout
```

Плагин — это MCP-сервер с манифестом. Такое решение принято сознательно: Yuki уже
умеет работать с MCP (ТЗ §19), и второй механизм расширения означал бы второй
реестр инструментов, второе место проверки разрешений и второй способ сломаться.
Манифест добавляет то, чего у голого MCP-сервера нет: имя, версию, заявленные
разрешения и заявленный список инструментов — то, что человек видит перед
установкой.

## Манифест

```json
{
  "id": "notes",
  "name": "Заметки",
  "version": "1.0.0",
  "description": "Быстрые заметки в локальный файл",
  "permissions": ["files"],
  "runtime": {
    "command": "python",
    "args": ["server.py"],
    "env": {}
  },
  "tools": ["add_note", "list_notes"]
}
```

| Поле              | Обязательное | Правила                                                                 |
| ----------------- | ------------ | ----------------------------------------------------------------------- |
| `id`              | да           | 2–64 символа, строчная латиница, цифры, `-`, `_`                        |
| `name`            | да           | непустое                                                                |
| `version`         | нет          | вид `1.0.0`, три числа; по умолчанию `0.1.0`                            |
| `description`     | нет          | одна строка для Hub                                                     |
| `permissions`     | нет          | категории из ТЗ §21 (см. ниже)                                          |
| `runtime.command` | да           | имя программы в PATH либо относительный путь внутри папки плагина       |
| `runtime.args`    | нет          | аргументы; не должны выходить за пределы папки плагина                  |
| `runtime.env`     | нет          | переменные окружения процесса плагина                                   |
| `tools`           | нет          | обещанные инструменты; сверяются с тем, что сервер отдал на самом деле  |

Категории разрешений: `microphone`, `screen_recording`, `accessibility`, `files`,
`network`, `shell`, `camera`, `notifications`, `browser`, `external_services`.

Валидация возвращает **все** замечания сразу, а не первое: править манифест
удобнее один раз.

## Программа плагина

Любой язык, который умеет читать строки из stdin и писать в stdout. Протокол —
JSON-RPC 2.0, по одному сообщению на строку. Минимум, который нужно поддержать:

| Метод                       | Что вернуть                                                    |
| --------------------------- | -------------------------------------------------------------- |
| `initialize`                | `protocolVersion`, `capabilities`, `serverInfo`                 |
| `notifications/initialized` | ничего — у уведомлений нет `id`                                 |
| `tools/list`                | `{ "tools": [...] }` с `name`, `description`, `inputSchema`     |
| `tools/call`                | `{ "content": [{ "type": "text", "text": "..." }] }`            |

Готовая заготовка на Python без внешних зависимостей создаётся командой
`scaffold_plugin` (или просьбой к Yuki «сделай плагин, который…»). Она сразу
работает: в ней есть инструмент `ping`, отвечающий на вызов.

Свои инструменты добавляются в двух местах `server.py` — в список `TOOLS` и в
ветки функции `call_tool`, — после чего имена дописываются в поле `tools`
манифеста.

Одна ловушка, о которой стоит знать заранее: **в stdout не должно попадать ничего,
кроме протокола**. Отладочная печать ломает разбор JSON-RPC; выводите диагностику
в stderr — Yuki показывает её последние строки в тексте ошибки подключения.

## Установка

| Источник     | Что происходит                                                        |
| ------------ | --------------------------------------------------------------------- |
| `local`      | папка копируется в каталог данных Yuki                                |
| `dev_folder` | папка остаётся на месте, правки видны после перезапуска плагина       |
| `git`        | `git clone --depth 1`, затем как `local`                               |
| `generated`  | то, что создала сама Yuki, — ставится тем же путём, что и чужое       |

Порядок всегда один: **чтение манифеста → валидация → показ того, что будет
запущено → согласие → запуск**. Установка без показа невозможна ни из интерфейса,
ни через инструмент модели: `install_plugin` помечен как действие высокого риска и
требует подтверждения (ТЗ §22).

После запуска Yuki сверяет обещанные инструменты с фактическими. Расхождение не
отменяет установку, но переводит возможность в состояние «работает частично» с
текстом причины: permission review опирается на манифест, и молчаливое
несоответствие обесценило бы его.

## Чем плагин изолирован, а чем нет

Изоляция ровно одна, и называть её надо честно: **отдельный процесс**. Плагин
запускается с правами пользователя и может всё, что может пользователь.
Валидация манифеста — не песочница и не защита от вредоносного кода, а проверка
того, что установка осознанна и что заявленное совпадает с действительным.

Реальная граница проходит по инструментам: всё, что плагин предлагает Yuki,
вызывается только через Permission Gate (ТЗ §21, §22), опасное действие требует
подтверждения, а выключение плагина сразу закрывает его процесс.

Отсюда практическое следствие: ставьте плагины только из источников, которым
доверяете, — ровно так же, как любую другую программу.

## Чего SDK пока не умеет

ТЗ §20 перечисляет, что плагин может добавлять: tools, commands, UI panels, AI
providers, voice providers, actions, triggers. Сейчас работают **tools** (через
MCP) и всё, что из них собирается: команды и автоматизации (ТЗ §16) строятся из
инструментов плагина наравне со встроенными.

UI-панели, провайдеры моделей и провайдеры голоса из плагинов не поддерживаются:
панель означала бы выполнение чужого кода внутри окна Yuki, где нет ни CSP-границы,
ни изоляции от остального интерфейса. Пока не сделана отдельная изоляция для этого,
таких точек расширения не будет — заявить их и не изолировать хуже, чем не иметь.
