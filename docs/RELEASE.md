# Выпуск и обновления

Закрывает пункт 2 из `docs/GAPS.md`: канал обновлений для приложения, которое
живёт на двух ОС.

## Что уже готово

- Плагин обновлений подключён, кнопка «Проверить обновления» есть в настройках.
- Сборка создаёт артефакты обновления (`createUpdaterArtifacts: true`).
- `.github/workflows/release.yml` собирает Windows и обе архитектуры macOS,
  прогоняет тесты и публикует черновик выпуска вместе с `latest.json`.

## Чего не хватает и почему это не сделано за вас

**Ключа подписи.** В `tauri.conf.json` поле `plugins.updater.pubkey` пустое, и
пока оно пустое, обновления **выключены целиком** — приложение честно говорит об
этом в настройках, а не делает вид, что канал работает.

Так и должно быть. Приватная половина ключа даёт право выпустить обновление от
имени автора, то есть запустить код на всех машинах, где стоит Yuki. Такой ключ
не создаётся за автора и не кладётся в репозиторий.

## Как включить обновления

Один раз:

```bash
npm run tauri -w @yuki/desktop -- signer generate -w ~/.yuki-updater.key
```

Команда напечатает две вещи:

1. **Публичный ключ** — вставьте его в `apps/desktop/src-tauri/tauri.conf.json`
   в `plugins.updater.pubkey` и закоммитьте. Он не секрет.
2. **Приватный ключ** — лежит в `~/.yuki-updater.key`. В репозиторий он не
   попадает никогда. Положите его содержимое в секреты GitHub:
   - `TAURI_SIGNING_PRIVATE_KEY` — содержимое файла целиком;
   - `TAURI_SIGNING_PRIVATE_KEY_PASSWORD` — пароль, если задавали.

Потеряли приватный ключ — сгенерируйте новый и обновите `pubkey`. Установленные
у людей копии перестанут видеть обновления и потребуют переустановки: клиент
проверяет подпись тем ключом, с которым его собрали.

## Как выпустить версию

1. Поднять версию в `apps/desktop/package.json`, `apps/desktop/src-tauri/tauri.conf.json`
   и `Cargo.toml` рабочего пространства — они должны совпадать, иначе клиент
   сравнит не то с не тем.
2. Записать изменения в `CHANGELOG.md`.
3. Поставить тег и запушить:

   ```bash
   git tag v0.2.0 && git push origin v0.2.0
   ```

4. Дождаться, пока соберутся все три таргета, проверить черновик выпуска и
   опубликовать его.

Выпуск публикуется черновиком намеренно: пока не собрались все три таргета,
выпуск с одним установщиком выглядит готовым и вводит в заблуждение — половина
пользователей увидит обновление, которого для их системы нет.

## Подпись самого приложения

Отдельно от подписи обновлений и здесь не настроено:

- **macOS** — Developer ID и нотаризация. Без них система показывает
  «приложение повреждено» при первом запуске. Нужны `APPLE_CERTIFICATE`,
  `APPLE_CERTIFICATE_PASSWORD`, `APPLE_SIGNING_IDENTITY`, `APPLE_ID`,
  `APPLE_PASSWORD`, `APPLE_TEAM_ID` в секретах.
- **Windows** — code signing certificate. Без него SmartScreen предупреждает
  о неизвестном издателе, но установка проходит.

Обе требуют платного аккаунта разработчика, поэтому оставлены на решение
владельца проекта. Канал обновлений от этого не зависит: он проверяет свою
подпись сам.
